# 학교 Microsoft 365 구성

학교의 M365 그룹·Teams를 정리하고 구성한다. **대상은 학교의 M365 관리자** —
대개 전문가가 아니라 그 역할을 떠맡은 선생님이다.

일반 교사용이 아니다. 그룹·팀을 만들려면 전역 관리자 권한이 필요하고,
일반 교사는 애초에 할 수 없는 일이다.

---

## 정한 것과 그 이유

### ① Graph를 기본으로 쓰지 않는다

`Microsoft.Graph` PowerShell은 **"Microsoft Graph Command Line Tools"** 라는 앱으로 붙는데,
`Group.ReadWrite.All` 같은 권한은 **관리자 동의가 필수**다. 학교마다 관리자가
낯선 이름의 앱에 넓은 권한을 승인하는 화면을 봐야 한다는 뜻이다 —
잘 모르는 관리자에게 최악의 첫 화면이고, 무서워서 거부하거나 아무 생각 없이 승인하게 된다.

반면 **`MicrosoftTeams` · `ExchangeOnlineManagement` 는 마이크로소프트 자체 모듈**이라
모든 테넌트에 이미 동의돼 있다. 전역 관리자면 동의 화면 없이 그냥 붙는다.
팀·M365 그룹·구성원은 전부 이 둘로 된다.

| 만들 것 | 모듈 | 동의 |
|---|---|---|
| Teams 팀 | `MicrosoftTeams` | 필요 없음 |
| M365 그룹 | `ExchangeOnlineManagement` | 필요 없음 |
| 구성원 | 같은 모듈들 | 필요 없음 |
| **Entra 보안 그룹** | Graph | **필요함 → 고급으로 뺌** |

보안 그룹만 Graph가 필요해서 **고급**으로 뺐다. 트리에 보안 그룹이 없으면
Graph는 아예 로드하지 않는다. (실제 운영에서도 보안 그룹은 손으로 만들어 왔다)

> 참고: 2025년 말부터 Exchange·Teams API에 대한 기본 동의 정책이 강화돼
> **서드파티** 앱은 관리자 동의가 필요해졌다. 자체 모듈을 쓰는 이 방식은 그 변화도 피해 간다.

### ② SDS를 감지하지 않는다 — 재고부터 본다

처음에는 SDS(School Data Sync)가 만든 그룹을 감지해 갈래를 나누려 했다.
감지는 가능하다 — SDS 확장 특성(앱 ID `fe2174665583431c953114ff7268b7b3`)이나
Graph의 `educationClass.externalSource = "sis"` 를 보면 된다.

**그런데 재고부터 보면 그 갈래 자체가 사라진다.**

무엇이 그것을 만들었든(SDS·손·다른 도구·전임 관리자) 할 일은 같다 —
**이미 있으면 안 만든다.** 원인은 미리보기를 보면 관리자가 안다.

감지를 넣지 않는 이유:

- 감지하려면 Graph 권한이 필요하다(위 ①과 충돌)
- 마이크로소프트가 SDS를 이미 한 번 갈아엎었다(Classic 종료, 팀 생성 기능이 빠졌다 돌아옴).
  표식에 기대면 그 변화에 또 끌려다닌다
- 재고 대조는 모든 원인을 덮는다

### ③ SDS를 쓰지 않는다

| | SDS | PowerShell (이 방식) |
|---|---|---|
| 명단 출처 | SIS → v2.1 규격 CSV | 아무 엑셀이나 |
| 학기 중 변경 | 자동 반영 | 다시 돌려야 함 |
| 초기 설정 | 무겁다 | 없음 |
| 통제권 | 규격이 정하는 대로 | 원하는 모양 그대로 |

**나이스(NEIS) 커넥터가 없다.** SDS의 최대 장점인 자동 동기화가 값어치 있는 건
SIS가 직결될 때인데, CSV를 손으로 만들어 올려야 한다면 그 일이 결국 남는다.
그럴 거면 엑셀에서 바로 PowerShell로 가는 게 짧다.

SDS가 이기는 지점(학기 중 명단 변동)은 **구성원 수렴**으로 메운다 —
"명단 갱신하고 다시 돌리기"가 한 번의 명령이 되게 한다. (아직 미구현)

### ④ 삭제보다 이름 변경이 먼저다

학교엔 지난 몇 년치 그룹이 어질러져 있다. 새 체계를 만들기 전에 그걸 정리해야 하는데,
**지우고 다시 만들면 파일·대화·팀이 전부 날아간다.** 이름만 바꾸면 내용을 그대로 두고
새 체계에 편입시킬 수 있다.

그래서 순서가 이렇다: **재고 보기 → 지울지 / 이름 바꿔 살릴지 결정 → 없는 것 만들기**

표시 이름과 별칭은 분리해 다룬다. 표시 이름만 바꾸면 안전하지만,
**별칭을 바꾸면 메일 주소가 바뀌어** 기존에 공유된 주소로 오던 메일이 끊긴다.

## 왜 상주 PowerShell 인가

다른 도구는 `Invoke-TeavelTool.ps1` 이 **호출마다 PowerShell 을 새로 띄운다.** 한 도구가
망가져도 다음 도구에 옮지 않아 그 편이 안전하다.

**M365 만 예외다.** `Connect-ExchangeOnline` 은 그 프로세스 안에서만 살아 있어서,
새로 띄울 때마다 브라우저 로그인이 다시 뜬다. 재고 보고 · 이름 바꾸고 · 만들고 하는 사이에
로그인이 예닐곱 번 뜬다는 뜻이다 — **로그인 창 하나도 버거워하는 분들에게는 못 쓰는 기능이다.**

그래서 `Invoke-TeavelM365Host.ps1` 하나를 띄워 두고 계속 쓴다.
`M365Host` 가 stdin 으로 요청을 한 줄씩 보내고 답을 읽는다.

```
teavel  ──JSON 한 줄──▶  상주 PowerShell
        ◀─진행 문구────   (그대로 화면에 흐른다)
        ◀─##TEAVEL##{…}   결과 한 줄
```

표시자(`##TEAVEL##`)를 붙이는 이유는 `Write-Host` 안내와 결과를 가르기 위해서다.
브라우저 로그인 설명은 **기다리는 동안** 보여야 하므로 결과에 담아 나중에 낼 수 없다.

상주 세션에서 부를 수 있는 함수는 **허용 목록**으로 제한한다. stdin 을 쥔 쪽이 이름을 그대로
실행할 수 있게 두면 무엇이든 부를 수 있게 된다.

## 흐름

```
① 대조    선언(트리) vs 테넌트 재고 → 계획
② 미리보기 만들 것 · 건너뛸 것 · 확인이 필요한 것을 이름까지
③ 확인    관리자가 승인해야 진행
④ 적용    없는 것만 만든다. 있으면 건드리지 않는다(여러 번 돌려도 안전)
⑤ 보고    만든 것 · 건너뛴 것 · 실패한 것을 각각
```

명령형("팀 24개 만들어")이 아니라 **선언형**("이 학교는 이런 모양이어야 한다")이다.
중간에 끊겨도 다시 돌리면 되고, 이미 있는 걸 덮어쓰지 않는다.

## 구조

```
catalog/m365-tree.json          학교 구조 선언 — 학교마다 이것만 바꾼다
src/Teavel.Core/M365/
  SchoolTree.cs                 읽기 · 펼치기 · 검증
  TreeReconciler.cs             재고 대조 → 계획
scripts/Teavel.M365.psm1        준비확인 · 연결 · 재고 · 이름변경 · 삭제
```

**판단은 전부 C#에 있고 PowerShell은 얇다.** 테넌트가 없어도 로직을 검증할 수 있어야 하기 때문이다.
PowerShell이 하는 일은 "목록 가져오기 / 하나 만들기 / 하나 고치기" 뿐이다.

### 트리 선언

`generate` 를 두면 곱집합으로 펼쳐진다.

```json
{ "id":"class", "kind":"team", "template":"educationClass",
  "displayName":"{학년}학년 {반}반", "mailNickname":"class-{학년}-{반}",
  "channels":["자율활동","진로활동","알림장"],
  "generate": { "학년":[1,2,3], "반":[1,2,3,4,5,6] } }
```

→ 18개 팀, 각 팀에 채널 3개. `kind` 는 `security` · `m365` · `team`.

채널 이름에도 `{학년}`·`{반}` 을 쓸 수 있다. `일반`(General)은 팀을 만들면 저절로 생기므로
적어도 걸러 낸다 — 적어 두면 만들다 실패한다.

채널도 **맞추는** 것이지 만드는 것이 아니다. 이미 있으면 건드리지 않고, 모자란 것만 만든다.
그래서 만들다 중간에 끊겨도 다시 돌리면 채워진다. 이 맞추기는 **만들 것이 없을 때도 돈다** —
팀은 다 만들어졌는데 채널에서 끊긴 실행은 그때가 유일한 복구 지점이기 때문이다.

## 실제 학교 테넌트에서 배운 것

작은 테넌트(그룹 11개) 하나를 열어 봤다. 거기서 나온 것들이 설계를 바꿨다.

### 별칭은 믿을 수 없다 — 대조는 이름으로

한글 이름으로 그룹을 만들면 별칭에서 뜻이 날아간다.

```
3학년_4반     →  3_4                 한글이 빠짐
3학년_과학     →  3_                  '과학' 이 통째로 사라짐
늘푸른 학생회   →  msteams_83a1ec      Teams 가 자동 생성
제주도 여행     →  949                 숫자만 남음
```

그래서 두 가지가 정해진다.

- Teavel 이 만들 때는 `mailNickname` 을 **영문으로 반드시** 받는다(이미 강제하고 있다).
- 기존 그룹과 대조할 때는 **표시 이름**을 기준으로 삼는다. 별칭은 보조일 뿐이다.

### 'All Company' 는 건드리면 안 된다

테넌트를 만들면 자동으로 생기는 조직 전체 그룹인데, **동적 그룹이라 구성원이 0명으로 온다.**
"구성원 없음 → 정리 후보" 로 넘기면 지우면 안 되는 것을 지우라고 권하게 된다.
별칭이 `AllCompany.<숫자>.<임의문자>` 꼴인 것으로 알아본다 — 이름은 테넌트 언어에 따라 달라진다.

### 정리 후보는 이름 생김새와 사람 수로 가른다

실제 테넌트에는 수업 그룹(30명·203명)과 시험용 잔재(`Test` `TEST` `테스트` `히히`, 1~2명)와
개인 그룹(`제주도 여행`)이 섞여 있었다. 관리자가 알고 싶은 것은 "무엇을 지워도 되나" 이고,
그 재료는 **이름의 생김새와 사람 수** 두 가지다.

`InventoryTriage` 가 셋으로 나눈다 — 쓰이는 것 / 정리 후보 / 건드리면 안 되는 것.
지우지는 않는다. 판단은 관리자가 하나씩 한다.

### 빈칸 하나로 반이 둘이 된다

가짜 테넌트에 실제 학교 목록을 넣고 돌려 보니, 테넌트의 `3학년_4반`(30명)을 두고
선언의 `3학년 4반` 을 **새로 만들려 했다.** 밑줄과 빈칸 하나 차이라 글자로는 다른 이름이다.
그대로 뒀으면 학교에 거의 같은 반이 둘 생기고 아이들이 어디로 들어갈지 몰랐을 것이다.

학교 이름은 손으로 붙여 온 것이라 표기가 제각각이다. 그래서 대조 전에
**빈칸 · 밑줄 · 붙임표 · 가운뎃점을 걷어내고 한 번 더 본다**(`TreeReconciler.Loosen`).
걸리면 만들지 않고 **확인 필요**로 세운다 — 지울지 이름을 맞출지는 사람이 정할 일이다.

걷어내는 것은 구분자뿐이다. 글자 자체를 건드리면 1반과 11반이 같아지는 식으로 엉뚱한 것이 겹친다.

### 만들고 끝내면 아무것도 안 보인다

**PowerShell 로 만든 팀은 담당 교사가 [활성화]를 누르기 전까지 학생에게 보이지 않는다.**
**새로 만든 채널도 접혀 있어 [...] → [표시]를 눌러야 목록에 나온다.**

이 두 가지는 Teavel 이 대신 해 줄 수 없다 — 교사 각자가 자기 Teams 앱에서 하는 일이다.
그런데 말해 주지 않으면 관리자는 다 됐다고 생각하고, 교사들은 "아무것도 안 보인다" 고 한다.
팀을 열일곱 개 만들었으면 문의도 열일곱 번이다.

그래서 만들기를 마치면 이 두 가지를 화면에 다시 알린다. "만들었습니다" 로 끝내지 않는다.

### 모듈 설치가 진짜 관문이다

실제 교사 PC(Windows 11 Pro 25H2, PowerShell 5.1)에서 EXO 모듈을 올리려다 다섯 겹에 걸렸다.

| 관문 | 증상 |
|---|---|
| TLS SystemDefault | 갤러리 연결 실패 |
| PSGallery Untrusted | "정말 하시겠습니까?" 에서 멈춤(비대화형이면 영영) |
| PowerShellGet 1.0.0.1 | 낡아서 `-Force` 가 안 먹는 구석이 있다 |
| PackageManagement 사용 중 | 갱신이 막힌다 — 새 프로세스가 필요 |
| **OneDrive 문서 폴더** | 폴더 백업이 켜져 있으면 모듈 경로가 `OneDrive\문서\` 로 간다 |

마지막 것이 특히 한국 학교에서 흔할 것이다. 경로를 짐작하면 반드시 틀리므로
**`$env:PSModulePath` 를 읽어야 한다.** 그리고 OneDrive 아래에 모듈을 두면
파일 온디맨드로 DLL 이 자리표시자가 되어 어셈블리 로드가 실패할 수 있다.

`Install-TeavelM365Module` 은 "있으면 넘어감" 이 아니라 **최소 버전을 봐야 한다** —
3.6.0 이 깔려 있으면 그대로 두고 나중에 없는 매개변수에서 터진다.

## 검증 상태

### 가짜 테넌트 (리눅스, 테넌트 불필요)

`PSModulePath` 에 가짜 `ExchangeOnlineManagement` · `MicrosoftTeams` 를 얹으면
**흐름 전체가 리눅스에서 돈다** — 상주 세션 · 주고받기 · 재고 읽기 · 분류 ·
이름 바꾸기 · 지우기 · 대조 · 만들기까지. 가짜에는 실제 학교에서 본 목록을 그대로 넣었다.

확인한 것:

- 로그인 → 재고 → 분류 → 정리 → 대조 → 만들기 한 바퀴
- **여러 번 돌려도 안전** — 2·3회차는 17개를 전부 건너뛰고 아무것도 만들지 않았다
- 이름 바꾸기(내용 유지) · 지우기(이름을 받아 적어야 실행)
- 허용 목록이 `Remove-Item` 을 막고, 깨진 JSON 에도 세션이 살아남음

여기서 **진짜 버그를 하나 잡았다.** `New-Team @args` — `$args` 는 param() 으로 받지 *못한*
인자를 담는 자동 변수라 늘 비어 있는데, splatting 은 비어 있어도 조용히 성공한다.
매개변수 하나 없이 호출돼 빈 그룹이 하나 생기고 그다음부터 전부 실패했으며,
오류 메시지는 엉뚱한 곳을 가리켰다. `teavel 자가점검` 이 이제 이 모양을 잡는다.

`Import-Module` 이 **판 번호가 아니라 PSModulePath 순서**로 고른다는 것도 여기서 알았다.

### 리눅스에서 확인한 것 (테넌트 불필요)

`SchoolTree` — 학년×반 18개 펼치기 · `generate` 없을 때 하나만 ·
못 채운 자리표시자 감지 · 한글 별칭 거부 · 별칭/이름 겹침 · `kind` 오타

`TreeReconciler` — 없으면 만들기 · 이미 있으면 건너뛰기 ·
팀 없는 그룹 감지 · 별칭 선점 감지 · 이름과 별칭이 서로 다른 그룹을 가리키는 경우

### 확인하지 못한 것

**실제 테넌트에서의 만들기·이름변경·삭제.** `Get-UnifiedGroup` 은 실제 테넌트에서 돌려 봤지만
`New-Team` · `Set-UnifiedGroup` · `Remove-UnifiedGroup` 은 가짜 테넌트에서만 돌았다.

SSH 로는 확인할 수 없다. Windows 의 SSH 세션은 바탕 화면이 없어
`Connect-ExchangeOnline` 이 로그인 창을 띄우지 못하고 이렇게 끝난다:

```
응용 프로그램이 UserInteractive 모드에서 실행되지 않을 때에는
모달 대화 상자나 폼을 표시할 수 없습니다.
```

**교사 PC 에서는 문제가 아니다** — 거기서는 사람이 앉아 있는 진짜 세션이다.
확인하려면 Windows 화면에서 직접 `teavel m365` 를 한 번 돌려 봐야 한다.

`Get-UnifiedGroup` 이 실제로 주는 것은 확인했다 —
`DisplayName` · `Alias` · `PrimarySmtpAddress` · `WhenCreated` ·
`ResourceProvisioningOptions`(팀 여부) · `GroupMemberCount` · `AccessType` 모두 온다.

## 이 방식은 어디서 왔나

새로 지어낸 것이 아니다. 실제로 학교에서 이 일을 해 온 순서를 그대로 옮긴 것이다.

```
나이스 [교육과정]-[과목 개설 관리]-[학생별 수강과목 편성]
  → 학급별 엑셀(학년-반.xls)
  → 엑셀/VBA 가 팀·채널 목록으로 정리
  → PowerShell 명령문을 문자열로 만들어 냄
  → 사람이 드래그해서 PowerShell 에 붙여넣기
```

쓰는 명령은 셋뿐이다 — `New-Team` · `New-TeamChannel` · `Add-TeamUser`.
**전부 MicrosoftTeams 모듈이고 Graph 가 나오지 않는다.** 우리가 고른 길과 같다.

Teavel 이 대신하는 것은 **마지막 두 줄**이다. 코드를 만들어 붙여넣는 대신,
선언과 재고를 대조해 없는 것만 만든다. 붙여넣기는 되돌릴 수 없고 중간에 끊기면
어디까지 됐는지 알 수 없지만, 대조는 여러 번 돌려도 안전하다.

고등학교는 선택과목 때문에 편성표만으로는 안 되고 나이스 자료가 필요하다는 것도
그 경험에서 나왔다. **나이스 내보내기를 트리의 출처로 삼는 것**이 다음 걸음이다.

## 명단 읽기

`teavel 명단 <파일>` — 아무 표나 받아 **학년·반·번호·학번·이름·표시이름·ID** 일곱 자리에 꽂는다.

**표시이름**은 Teams 에서 보이는 이름이고 `학번+이름` 꼴이다(`10401홍길동`).

### 양식을 정해 주지 않는다

학교마다 엑셀 모양이 다르다. "이 양식에 맞춰 오세요" 라고 하면 아무것도 모르는 관리자는
거기서 막힌다. **맞추는 쪽은 Teavel 이다.**

```
학년 ← 2번째 열 '학 년'        ('학 년' 은(는) 학년 입니다, 값도 맞습니다)
반   ← 3번째 열 '학급'         ('학급' 은(는) 반 입니다, 값도 맞습니다)
ID   ←?6번째 열 '사용자 ID(메일)'  ('사용자 ID(메일)' 안에 'id' 이(가) 있습니다)
```

대신 **무엇을 어떻게 봤는지 반드시 보여 준다.** 조용히 틀리면 아이가 다른 반에 들어간다.
`?` 표시는 완전 일치가 아니라는 뜻이다.

판단은 이렇게 한다.

- 열 이름을 다듬어(빈칸·줄바꿈·괄호 설명 제거) **완전 일치**를 가장 세게 본다
- 부분 일치는 약하게 본다. 한 글자짜리('반'·'번')는 부분 일치를 아예 안 쓴다 —
  **'일반계' 안의 '반'** 을 학급으로 읽으면 안 되기 때문이다
- **'학년도' 는 학년이 아니다.** 이런 것은 점수 이전에 잘라 낸다
- 값의 생김새도 본다. 열 이름이 `열1` 뿐이어도 값이 1~6이면 학년으로 본다
- 한 열이 두 자리를 차지할 수 없다. 점수 높은 짝부터 확정해 **'학번' 과 '번호' 가
  서로를 밀어내게** 한다
- 머리글이 첫 줄이라는 보장이 없다. 줄마다 꽂아 보고 가장 많이 꽂히는 줄을 머리글로 본다

### 데이터 형식과 보고서 형식을 가른다

선생님들이 주는 명단은 두 모양이다. **어느 쪽인지도 Teavel 이 알아본다.**

**데이터 형식** — 줄마다 학년·반이 다 적혀 있다. 그대로 읽으면 된다.

**보고서 형식** — `1학년 3반` 이 제목으로 한 번 나오고 그 아래에 번호·이름만 있다.
사람이 보기엔 당연하지만, 줄만 읽으면 그 학생들이 몇 학년 몇 반인지 알 수 없다.
그래서 제목처럼 생긴 줄에서 학년·반을 읽어 **다음 제목이 나올 때까지 아래로 물려준다.**
한 파일에 여러 반이 이어 붙어 있는 것도 이것으로 갈린다.

제목 줄은 **칸이 몇 개 안 찬 줄**에서만 찾는다. 줄마다 값이 꽉 찬 명단 줄에서 찾으면
`3학년_4반` 같은 그룹 이름이 든 칸을 제목으로 오해한다.

보고서 형식은 반이 바뀔 때마다 **열 이름 줄을 다시 찍는다.** 그것을 학생으로 읽으면
이름이 '성명' 인 아이가 생기므로, 값이 든 칸이 전부 열 이름과 같으면 건너뛴다.

### Office 없이 읽는다

지금까지 표 읽기는 엑셀 COM 하나였는데, **한셀만 깔린 PC 에서는 아무것도 못 한다.**

그래서 csv 와 xlsx 는 직접 읽는다 — csv 는 글자일 뿐이고 xlsx 는 zip 안의 xml 이다.
한셀도 그 둘로 저장할 수 있으므로 대부분 통한다.

| | 읽는 법 |
|---|---|
| `.csv` `.txt` `.tsv` | 직접. **CP949 를 자동으로 알아본다** |
| `.xlsx` `.xlsm` | 직접(zip+xml). 엑셀이 없어도 된다 |
| `.hwpx` | 직접(zip+xml). **한글이 없어도 된다.** 표 중 가장 큰 것을 명단으로 본다 |
| `.xls` `.cell` `.hwp` | 아직 못 읽음 — 어느 프로그램에서 무엇을 누를지 적어 준다 |

`.hwp` 는 압축된 이진 덩어리라 규격을 구현해야 한다. 대신 **한글에서 `.hwpx` 로 한 번
저장해 달라고 한다** — 그 정도는 할 수 있는 일이다. `.hwpx` 는 xlsx 처럼 zip 안의 xml 이다.

한국 학교 csv 는 대개 CP949 라 UTF-8 로 읽으면 이름이 전부 깨진다.
UTF-8 로 먼저 읽어 보고 깨진 글자가 나오면 CP949 로 다시 읽는다. 순서가 반대면 안 된다 —
CP949 는 아무 바이트나 받아들여 깨진 줄도 모르고 넘어간다.

### 없는 자리는 만들어 채운다

일곱 자리가 다 있는 파일은 드물다. 그런데 없는 것 중 상당수는 있는 것으로 만들 수 있다.

| 없을 때 | 무엇으로 |
|---|---|
| 학번 | 학년·반·번호를 이어 붙여 (`1`,`4`,`1` → `10401`) |
| 표시이름 | 학번+이름 (`10401`+`홍길동` → `10401홍길동`) |
| 학번·이름 | 표시이름을 갈라 (`30105강도윤` → `30105`,`강도윤`) |
| 학년·반·번호 | 학번을 갈라 (`30105` → 3학년 1반 5번) |
| 학년·반 | 위쪽 제목줄에서 물려받아 (보고서 형식) |

마지막 두 개가 없으면 **어느 반에 넣을지를 알 수 없어 배정 자체가 안 된다.**

### 학번 규칙은 학교마다 다르다

1학년 3반 1번이 `10301` 인 학교도 있고 `1301` 인 학교도 있다. 실제로 한 학교에서
`1301`(1학년 3반 1번)과 `21005`(2학년 10반 5번)를 함께 봤다 — 반을 자리에 맞춰 채우지 않는다.
여기를 박아 두면 절반의 학교에서 틀린다.

그래서 **자료에서 알아낸다.**

- 파일에 학번과 학년·반·번호가 함께 있으면 **맞춰 보면 안다.** 어느 형식으로 이어 붙였을 때
  실제 학번과 같아지는지 세어 보면 되고, 이때는 짐작이 아니라 확인이다.
- 학번 열이 없어도 **아이디나 표시이름 안에 들어 있다** — `s10203@…` · `30105강도윤`.
  거기서 찾아내면 사람에게 아무것도 묻지 않는다.
- 그래도 하나로 안 정해지면 **보기를 들어 묻는다.** "1학년 3반 1번 → 10301 입니까, 1301 입니까".
  숫자를 보면 누구나 답할 수 있다.

숫자 덩어리가 둘 이상이면(`2026-10203`) 어느 쪽이 학번인지 알 수 없으므로 짐작하지 않는다.

만들어 채운 값은 **무엇으로 만들었는지까지 화면에 적는다.** 자리 이름만 말하면
'학년·반·번호를 이어 붙였다' 는 문장이 그 열이 없는 파일에도 나가 거짓말이 된다.

### 밀린 줄

csv 에서 가운데 칸이 하나 빠지면 **그 뒤가 통째로 한 칸 앞으로 밀린다.**
이름 자리에 아이디가 들어가는데 화면만 보면 그럴듯하다. 그래서 칸 수가 다른 줄을 짚어 준다.

xlsx 는 칸마다 `C5` 같은 자리표가 붙어 있어 밀릴 수가 없다. 거기서는 이 경고를 하지 않는다.

## 갈림길 — 한꺼번에 만들 것인가, 이미 있는 계정을 쓸 것인가

학생 계정은 두 갈래로 생긴다. **학생이 스스로 만들거나, 관리자가 한꺼번에 만들거나.**
이미 있는 계정을 쓰는 자리에서 또 만들면 같은 사람이 둘이 되고, 없는 계정에 배정하려 들면
한 줄도 못 넣는다. 그래서 이 선택은 반드시 사람이 한다.

### 한꺼번에 만들기

계정 만들기는 Exchange·Teams 모듈로 못 한다. Graph 아니면 관리 센터인데
Graph 는 동의 화면을 부르므로, **관리 센터에 올릴 csv 를 만들어 주는 쪽**을 골랐다.
동의 화면이 없고, 학생 개인 정보가 우리 코드를 거쳐 어디로도 나가지 않는다.

문제는 열 이름이다. 마이크로소프트 문서가 **"견본과 열 이름이 정확히 같아야 한다"** 고
못 박는데 그 이름은 포털 언어와 판에 따라 다르다. 그래서 **관리자가 내려받은 견본을 받아
그 머리글을 그대로 쓴다.** 우리가 이름을 짐작하지 않는다 — 틀리면 올리는 순간 통째로 거부당한다.
(견본을 읽는 것도 결국 같은 일이라 명단 읽기 코드를 그대로 쓴다)

한국 이름은 성과 이름을 가르지 않는다. 억지로 쪼개면 '홍' 과 '길동' 이 되어 과제 화면에서
이상해지므로, 성 자리에 통이름을 넣고 표시 이름을 제대로 채운다.

만든 csv 는 **BOM 을 붙여 쓴다.** 없으면 관리자가 올리기 전에 엑셀로 열어 볼 때
이름이 전부 깨져 보이고, 잘못된 줄 알고 손대게 된다.

## 남은 일

1. **`Teavel.M365.psm1` 실기 검증** — Windows에서 실제 테넌트에 붙여 보기.
   특히 `Get-UnifiedGroup` 의 어떤 속성이 실제로 오는지(`GroupMemberCount`, `AccessType`,
   `ResourceProvisioningOptions`) 확인이 필요하다.
2. **재고 화면 설계** — 그룹이 100개면 하나씩 물을 수 없다.
   실제 학교의 목록이 어떻게 생겼는지 보고 묶는 방식을 정한다.
3. **실제 테넌트에서 한 바퀴** — Windows 화면에서 직접. 가짜에서는 다 돌았다.
4. **구성원 수렴** — 명단 엑셀 대비 추가·제거. SDS를 안 쓰는 대가를 치르지 않으려면 필요하다.
5. **보안 그룹(고급)** — Graph 경로. 트리에 보안 그룹이 있을 때만.
   지금은 계획에서 갈라 내어 "관리 센터에서 손으로 만들어 주세요" 라고 분명히 말한다.
6. **명단 → 배정** — `teavel 명단` 이 읽어 낸 것을 `Add-TeamUser` 로 넣는 부분.
   `Role Owner`(교사) / `Member`(학생). 지금은 어느 반에 몇 명인지 보여 주는 데까지다.
8. **나이스 수강과목 편성 → 트리** — 지금 트리는 손으로 쓴 JSON 이다.
   고등학교 선택과목은 나이스 자료가 있어야 한다.
9. **학번 ID 일괄 변경** — 신학기마다 필요하다(`10101…` → `20101…`).
   예전 방식의 `Set-MsolUser` 는 2025년 5월에 퇴역해 다른 길을 찾아야 한다.
