# 학년이 끝나면 — Microsoft 365 정리

졸업생과 지난해 팀을 정리한다. **대상은 [학교 M365 구성](m365.md)과 같다** —
전문가가 아니라 그 역할을 떠맡은 선생님이다.

구성이 "없는 것을 만드는 일"이라면 정리는 **"있는 것을 없애는 일"**이다.
되돌릴 수 없는 쪽이라 규칙이 더 많다.

이 문서는 실제 학교 테넌트(`nprm.goe.go.kr`, 395명)를 2026-08-20에 한 바퀴 돌린 결과다.
짐작으로 쓴 문장이 없다.

---

## 정한 것과 그 이유

### ① 학년이 단위다 — 사람이 아니라 묶음을 받는다

졸업생 정리는 **한 사람씩 고르는 일이 아니다.** 3학년이 통째로 나간다.
실제 테넌트에서 그 수가 **202명**이었다.

체크박스 202개짜리 화면은 도구가 아니다. 관리자는 그 화면을 닫는다.
그래서 정리 명령은 **사람이 아니라 묶음(cohort)을 받아야 한다.**

```
3학년 전체   202명   [유지] [차단] [삭제]
  3학년 1반   28명   [유지] [차단] [삭제]
  3학년 2반   30명   [유지] [차단] [삭제]
```

학년 줄을 누르면 그 아래 반이 전부 따라온다. 반 하나만 되돌리면 학년 줄은
**'섞여 있음'** 으로 바뀐다. 사람이 지금 무엇을 고른 상태인지 한눈에 알아야 한다.

### ② 학년·반은 표시 이름에서 읽는다 — 디렉터리 속성은 비어 있다

[m365.md 의 '이름 — 교사와 학생을 가르는 뼈대'](m365.md) 에서 학생 표시 이름을
`학번+이름` 으로 두자고 정했다. **그 결정이 실기에서 값을 다 했다.**

실제 테넌트에서 쓸 수 있었던 것은 표시 이름 하나뿐이다.

| 속성 | 채워진 사람 |
|---|---|
| `Department` | **0명** |
| `Title` | **0명** |
| `City` | **0명** |
| `MailboxItems`(사용량) | **0명** |
| **표시 이름의 학번** | **210명** |

`Department` 로 교사와 학생을 가르는 설계는 **실제 학교에서 작동하지 않는다.**
교육청 포털로 계정이 들어오면 그 칸들이 비어 있다. 아무도 채우지 않는다.

```
10101강민서   ->  1학년 01반 01번 강민서
30410박다움   ->  3학년 04반 10번 박다움
```

교차검증도 됐다 — `3학년_과학` 팀 구성원 203명 = 학번이 3학년인 202명 + 소유자 1명(교사).
정확히 맞는다.

> 학번 형식은 학교마다 다르다. [m365.md 의 '학번 규칙은 학교마다 다르다'](m365.md) 에서
> 정한 대로 **자료에서 알아내고, 못 정하면 보기를 들어 묻는다.** 여기에 `\d{5}` 를 박아 두지 않는다.

### ③ 학번은 지금 학년이 아니다 — 만든 때의 학년이다

**이게 이 문서에서 가장 위험한 곳이다.**

표시 이름의 학번은 계정을 만들 때 찍힌 값이다. 매년 고쳐 주지 않으면 그대로 남는다.
`30101` 이 올해 3학년이라는 뜻이 아니다.

그래서 **묶음을 보여줄 때 계정 생성 연도를 반드시 같이 보여준다.**

```
3학년 전체   202명   계정 생성 2023, 2025
```

실제 테넌트에서는 202명 중 199명이 2025년 생성이고 활동 기록이 없었다 →
2025학년도 3학년 → 2026년 2월 졸업. 읽어 낼 수 있었다.

만약 학교가 신학기마다 학번을 고쳐 준다면(→ [m365.md '남은 일' 9번](m365.md))
`30101` 은 **올해 3학년**이고 아직 졸업하지 않았다. 정반대다.

**그래서 도구가 판정하지 않는다.** 근거를 늘어놓고 사람이 누르게 한다.
"졸업생 202명을 찾았습니다" 라고 말하는 순간 그 도구는 위험해진다.

### ④ 교사는 자동으로 못 가린다 — 대신 결과를 테넌트에 남긴다

학번이 없는 사람이 185명이었다. 그 안에 교사·옛 졸업생·테스트 계정이 섞여 있고,
**가를 방법이 없다.**

| 단서 | 인원 | 왜 부족한가 |
|---|---|---|
| 학번이 없다 | 185 | 옛 졸업생·테스트 계정이 섞인다 |
| 도메인이 다르다(`mnpr.goedu.kr`) | 9 | 학교 교사 수보다 훨씬 적다 |
| 그룹 소유자다 | 4 | **학생도 팀을 만든다** (`히히` 팀 소유자가 3학년 학생이었다) |

셋을 합쳐도 13명이다. 교사 전원이 아니다.

**그러니 자동 분류를 시도하지 않는다.** 후보만 표시하고 체크는 사람이 한다.
대신 **한 번 가른 결과를 테넌트 안에 `교사` M365 그룹으로 남긴다.**

내년 정리 때는 그 그룹이 곧 명단이다. 이 화면이 필요 없어진다.
**정리 도구가 스스로 다음 해를 쉽게 만든다.** 이게 이 설계의 핵심이다.

`New-UnifiedGroup` + `Add-UnifiedGroupLinks` 면 되므로 **Graph 는 여기서도 필요 없다.**

### ⑤ 되돌릴 수 있는 것부터 — 순서가 안전장치다

```
0) 교사 그룹 만들기   되돌리기 쉬움 — 그룹만 지우면 된다
1) 이름 변경          되돌리기 쉬움 — 다시 바꾸면 된다
2) 아카이브·내보내기  되돌릴 수 있음 — 다시 넣으면 된다
3) 계정 차단          되돌릴 수 있음 — 다시 켜면 된다
4) 삭제               30일 뒤 되돌릴 수 없음
```

**이 순서를 사용자가 바꾸지 못하게 한다.** 순서 자체가 안전장치다.

계정을 먼저 지우면 그룹 소유자가 사라져 **주인 없는 그룹**이 남는다.
그래서 그룹 삭제가 계정 삭제보다 앞에 온다.

기본은 **미리보기**다. 아무것도 바꾸지 않는다. 실행에는 별도의 스위치가 필요하고,
**삭제에는 스위치가 하나 더 필요하다.** 실수로 `-Execute` 를 붙여도 지워지지 않는다.

> **차단이 삭제보다 거의 항상 낫다.** 차단은 로그인만 막고 메일·OneDrive 는 그대로 둔다.
> 언제든 되돌릴 수 있다. 삭제는 30일 뒤 끝이고 파일도 함께 사라진다.
> 화면에서 이 말을 하되, 관리자가 삭제를 고르면 **막지 않는다.** 결정은 학교의 몫이다.

### ⑥ 사람이 고르고 기계가 실행한다

정리는 **한 번에 끝나지 않는다.** 관리자가 화면을 열어 두고 며칠 들여다보고,
교감 선생님께 물어보고, 다시 와서 고친다.

그래서 **고르는 일과 실행하는 일을 파일 하나로 끊는다.**

```
재고(CSV) → 검토 화면(HTML 한 장) → 결정 파일(JSON) → 실행
```

검토 화면은 **데이터를 안에 박아 넣은 HTML 한 장**이다. `file://` 에서 `fetch` 가
CORS 로 막히기 때문이고, 실제 학생 이름이 들어 있어 **어디에도 올리지 않기** 때문이다.

결정 파일은 **사람이 읽을 수 있어야 한다.** 실행 전에 관리자가 열어 볼 수 있고,
무슨 일이 일어날지 파일만 보고 알 수 있어야 한다.

### ⑦ 두 번 돌려도 안전해야 한다

네트워크가 끊기고, 스로틀링에 걸리고, 관리자가 중간에 창을 닫는다.
**다시 돌렸을 때 같은 일이 두 번 일어나면 안 된다.**

- 이름이 이미 그 이름이면 건너뛴다
- 이미 그룹에서 빠진 사람은 건너뛴다
- 이미 차단된 계정은 건너뛴다
- 이미 구성원인 사람은 다시 넣지 않는다
- 같은 이름의 그룹이 이미 있으면 새로 만들지 않고 그 그룹을 쓴다

그리고 **모든 단계가 실행 시점에 대상을 다시 조회한다.** 재고를 뜬 뒤 며칠이 지났을 수 있다.
없어졌으면 건너뛰고, 이름이 바뀌었으면 알린다.

## 흐름

```
1. 재고        Get-TeavelM365Inventory        읽기 전용
2. 해독        Get-TeavelStudentId            표시 이름 → 학년·반·번호
3. 묶음        Get-TeavelCohort               학년·반 단위로 묶기
4. 검토 화면   Export-TeavelCleanupReview     HTML 한 장 (데이터 내장)
      ↓  관리자가 고른다. 며칠 걸려도 된다.
5. 결정 파일   m365-decisions.json
6. 미리보기    Invoke-TeavelCleanupPlan       기본값 — 아무것도 안 바꾼다
7. 실행        Invoke-TeavelCleanupPlan -Execute
8. 삭제        Invoke-TeavelCleanupPlan -Execute -ConfirmDelete
```

### 만들 것

| 함수 | 하는 일 | 쓰는 cmdlet |
|---|---|---|
| `Get-TeavelStudentId` | 표시 이름에서 학년·반·번호·이름을 뽑는다. 형식은 설정으로 받는다 | 없음 (문자열) |
| `Get-TeavelCohort` | 학년 묶음·반 묶음·학번없음 묶음을 만든다. 각 묶음에 **계정 생성 연도**를 붙인다 | 없음 |
| `Export-TeavelCleanupReview` | 재고 + 묶음 → HTML 한 장 | 없음 |
| `Invoke-TeavelCleanupPlan` | 결정 파일을 읽어 순서대로 실행. 미리보기가 기본 | 아래 전부 |
| `New-TeavelTeacherGroup` | 교사 그룹을 만들고 채운다. 있으면 재사용 | `New-UnifiedGroup` · `Add-UnifiedGroupLinks` |

실행 단계가 쓰는 cmdlet — **전부 `ExchangeOnlineManagement` 하나다.**

| 단계 | cmdlet |
|---|---|
| 그룹 이름 변경 | `Set-UnifiedGroup -DisplayName` |
| 구성원 내보내기 | `Remove-UnifiedGroupLinks -LinkType Members` |
| 그룹 삭제 | `Remove-UnifiedGroup` |
| 계정 표시 이름 변경 | `Set-User -DisplayName` |
| **계정 차단** | `Set-User -AccountDisabled $true` |
| 계정 삭제 | `Remove-Mailbox` |

`Set-User -AccountDisabled` 가 중요하다. **계정 차단에 Graph 도 AzureAD 모듈도 필요 없다.**
정리의 핵심 동작(차단)이 EXO 하나로 된다는 뜻이고, [m365.md ①](m365.md) 의 전제가 정리에서도 지켜진다.

계정 **삭제**만 사정이 다르다. EXO 로는 Entra 사용자 개체를 직접 지울 수 없다.
클라우드 전용 계정이면 `Remove-Mailbox` 가 사서함과 함께 계정까지 지우지만,
**되돌리기 어려운 동작이라 스위치로 잠근다.** 권장 경로는 여전히 차단 → 유예 → 삭제다.

### 검토 화면이 갖춰야 할 것

- **탭 넷** — 그룹·팀 / 학년·반 / 교사 / 계정 전체
- 기본값은 전부 **유지**. 바꾼 것만 저장한다
- **보호 대상은 화면에서 잠근다** — `All Company`, 시스템 도메인 계정, 사서함 없는 개체.
  고를 수 없게 만든다. 경고문으로는 부족하다
- 삭제를 20명 넘게 고르면 **저장 직전에 반별 인원을 보여주고** 한 번 더 확인받는다.
  "202명" 보다 "3학년 1반 28명 · 2반 30명 …" 이 훨씬 무겁게 읽힌다
- 아카이브는 **소유자를 구성원에서 빼지 않는다.** 빼면 담당 선생님이 그 팀의 파일과
  대화에 접근하지 못한다

## 실제 테넌트에서 배운 것

`nprm.goe.go.kr` · 395명 · 그룹 11개 · 2026-08-20

### 내보내기가 낭비인 경우가 있다

`3학년_과학` 팀을 아카이브(이름 변경 + 소유자 외 내보내기)하기로 하고,
같은 202명을 계정 삭제하기로 했다. **내보낼 202명과 지울 202명이 완전히 같았다.**

계정을 지우면 그룹에서도 자동으로 빠진다. 내보내기 202회는 **순수한 낭비**였다 —
수 분이 걸리고 스로틀링 위험만 있다.

**그래서 실행 전에 겹침을 검사하고 알려 준다.** "내보낼 202명이 모두 삭제 대상입니다.
내보내기를 건너뛸까요?" 결정은 사람이 하되, **도구가 먼저 알아채야 한다.**

반대로 삭제를 유예하기로 하면 내보내기가 실제로 필요하다. 그래서 자동으로 빼지 않고 묻는다.

### 소유자 확인은 스냅샷이 아니라 '지금'을 봐야 한다

계정을 지우기 전에 **아직 그룹 소유자인지** 확인해야 한다. 소유자를 지우면 주인 없는 그룹이 남는다.

그런데 그 확인을 **결정 파일에 적힌 재고 시점 정보**로 하면 틀린다.
실제로 이 함정에 빠졌다 — 학생 둘이 `테스트`·`히히` 팀의 소유자였는데,
**그 팀들도 같은 실행에서 삭제**된다. 그룹이 지워진 뒤인데도 스냅샷을 보고 삭제를 거부했다.

**계정 삭제 직전에 소유자 관계를 다시 읽는다.** 그룹이 11개뿐이라 비싸지 않다.
읽지 못하면 **계정 삭제를 통째로 중단한다** — 모르는 채로 지우는 것보다 낫다.

### 학생도 팀을 만든다

`히히`(설명 "유튭") 와 `테스트` 의 소유자가 3학년 학생이었다.
**'그룹 소유자 = 교사' 라는 가정은 틀린다.** 교사 후보의 단서로만 쓰고 판정에 쓰지 않는다.

### 이상한 계정은 그냥 있다

`nprm.goe.go.kr@nprm.goe.go.kr` — 도메인 이름이 아이디로 들어간 계정이 실제로 있었다.
표시 이름은 멀쩡한 학번+이름이다. **아이디 모양으로 무엇을 판단하면 안 된다.**

### 재고 시점의 이름을 믿지 않는다

사전 점검에서 대상마다 **지금 이름**을 다시 읽고, 재고 때와 다르면 알린다.
그 사이에 관리자가 관리 센터에서 손으로 고쳤을 수 있다.

## PowerShell 함정 — 한국어 스크립트에서 반복해서 만난다

### `"$g학년"` 은 `$g학년` 이라는 변수다

```powershell
$g = '3'
"$g학년 전체"      # -> ' 전체'       한글은 변수 이름에 쓸 수 있는 문자다
"${g}학년 전체"    # -> '3학년 전체'
```

**오류가 나지 않고 조용히 빈 문자열이 된다.** 화면에 레이블만 빠진 채 나와서
데이터 문제로 착각하기 딱 좋다. 실제로 그렇게 헤맸다.

변수 바로 뒤에 한글이 붙으면 **무조건 `${}` 로 감싼다.** 검사는 쉽다:

```powershell
Select-String -Pattern '\$[A-Za-z_][A-Za-z0-9_]*[가-힣]' -Path *.ps1
```

### `@($list)` 가 `List[object]` 에서 터진다

```powershell
$L = New-Object System.Collections.Generic.List[object]
$L.Add([pscustomobject]@{a=1})
@($L)          # ArgumentException: Argument types do not match
$L.ToArray()   # 정상
```

메시지가 원인을 전혀 안 가린다. `ConvertTo-Json` 이나 파일 쓰기에서 터진 줄 알고
한참 엉뚱한 데를 봤다. **List 를 배열로 만들 때는 `.ToArray()` 를 쓴다.**

`Teavel.*.psm1` 은 누적 컬렉션에 List 를 쓰는 곳이 많아 전수 점검이 필요하다.

### 한글이 든 `.ps1` 은 UTF-8 BOM 으로 저장한다

Windows PowerShell 5.1 은 BOM 없는 `.ps1` 을 CP949 로 읽는다. 한글 UTF-8 바이트가
CP949 선행 바이트로 오인되면 **뒤따르는 따옴표나 중괄호를 삼켜** 실제 원인과 무관한 줄에서
문법 오류가 난다. `Export-Csv` 도 `-Encoding UTF8` 을 명시한다.

### 로그는 파일이 진실이다

콘솔 QuickEdit 선택 모드에서 출력이 통째로 막힌다. 202건을 도는 도중에 멈춘 것처럼 보인다.
**모든 동작을 파일에 남기고, 결과를 CSV 로도 낸다.** 관리자가 나중에 무엇이 일어났는지
확인할 수 있어야 한다.

## 남은 일

1. **학번 형식 자동 판별** — 지금은 `\d{5}` 를 가정했다.
   [m365.md '학번 규칙은 학교마다 다르다'](m365.md) 의 방식(자료에서 알아내고, 못 정하면 보기로 묻기)을
   정리 쪽에도 붙여야 한다.
2. **명단 대조와 합치기** — 엑셀 명단이 있으면 학번 해독보다 정확하다.
   명단이 있으면 명단을 쓰고, 없으면 학번을 쓴다. 지금 문서는 **명단이 없을 때**를 다룬다.
3. **교사 그룹을 재고가 읽어 쓰기** — `교사` 그룹이 이미 있으면 그 구성원을 교사로 보고
   검토 화면의 교사 탭을 미리 채운다. ④ 의 순환이 완성되는 자리다.
4. **차단 후 유예 관리** — 언제 차단했는지 기록해 두고 "차단한 지 6개월 지난 계정" 을
   다음 정리 때 보여준다. 지금은 차단하고 잊어버린다.
5. **스로틀링** — 202건까지는 문제없었다. 1000명 학교에서 확인이 필요하다.
6. **팀 아카이브 기능** — Teams 에는 팀을 '보관' 하는 기능이 따로 있다(`Set-TeamArchivedState`).
   이름 변경 + 내보내기보다 나을 수 있다. `MicrosoftTeams` 모듈이 필요하므로
   [m365.md '로그인은 한 번이어야 한다'](m365.md) 의 원칙대로 **실패해도 치명적이지 않게** 다뤄야 한다.
