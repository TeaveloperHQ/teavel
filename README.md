# Teavel

**선생님 컴퓨터를 대신 세팅해 주는 에이전트.** 교사 PC의 PowerShell에서 돌고,
인터넷을 쓰지 않는다.

> 만든 이유는 단순하다. 선생님들이 PC 세팅을 못 한다. 못 하는 게 당연하다 —
> "회사 또는 학교 액세스" 같은 화면을 왜 알아야 하나.

교사 PC는 대개 로컬 계정(`user`)으로만 쓰인다. **Windows에 학교 계정이 붙어 있지 않다.**
그래서 원드라이브·아웃룩·팀즈·To Do가 저마다 로그인을 요구하고, 같은 비밀번호를
네 번 넣다가 포기한다. 그 하나를 풀면 나머지가 줄줄이 딸려 온다.

```
> 점검

① 이 컴퓨터와 계정 — 먼저 정해 둘 것
  ! 컴퓨터 이름 — 'DESKTOP-4K7QX2' 입니다. 알아보기 어려운 이름입니다.
  ! Windows 에 학교 계정 잇기 — 연결돼 있지 않습니다.
        ↑ 이것부터 하시면 아래 것들이 대부분 함께 해결됩니다.
  ! OneDrive 로그인 — 로그인돼 있지 않습니다.
  ✓ Office 학교 계정 로그인 — 계정 1개가 연결돼 있습니다.

② 자료 지키기 — 잃어버리지 않게
  ! 바탕 화면·문서·사진 백업 — 3개 폴더가 백업되지 않고 있습니다.

③ 프로그램 — 쓸 것들 갖추기
  ✓ Office(워드·엑셀·파워포인트) 설치 — 엑셀·워드·아웃룩 모두 쓸 수 있습니다.
  ! To Do 설치 — 설치돼 있지 않습니다.

④ 인쇄
  ! 기본 프린터 — 프린터 3대. 기본 프린터가 정해져 있지 않습니다.
```

`고침`을 치면 순서대로 하나씩 손본다. 비밀번호가 필요한 일은 **대신 해 주는 척하지 않고**
정확한 설정 화면을 열어 클릭 순서를 알려 준다.

## 선생님용

> **선생님이 읽으실 것은 [docs/사용법.md](docs/사용법.md) 입니다.**
> 이 아래는 만든 사람을 위한 설명이 섞여 있습니다.

처음 한 번만 — 압축을 푼 폴더에서 PowerShell을 열고:

```powershell
.\teavel.exe 설치
```

이걸로 두 가지가 됩니다.

**① 어느 폴더에서든 `teavel`** — 새 PowerShell 창부터 적용됩니다.

**② 폴더 우클릭 → [여기서 Teavel 열기]** — 이쪽이 실제로 더 편합니다.
교사 업무는 대부분 폴더 단위인데, 이렇게 열면 **폴더 경로를 치지 않아도 됩니다.**

```
> 엑셀 다 합쳐줘

  엑셀 파일 여러 개를 하나로 합치기
      폴더 (그냥 Enter 면 현재 폴더: 2반 수행평가):     ← Enter
      저장할 파일: 통합.xlsx                          ← 짧게 쳐도 됨
```

사용자 설정만 건드리므로 관리자 권한이 필요 없고, `teavel 제거` 로 되돌립니다
(프로그램 파일은 지우지 않습니다). Windows 11에서는 우클릭 후 **[추가 옵션 표시]** 안에 들어갑니다.

| 명령 | 하는 일 |
|---|---|
| **`teavel 점검`** | **지금 무엇이 안 돼 있는지 봅니다 — 여기서 시작하세요** |
| **`teavel 고침`** | **순서대로 하나씩 손봅니다** |
| `teavel` | 하고 싶은 일을 말로 적으면 처리합니다 |
| `teavel 목록` | 할 수 있는 일을 보여줍니다 |
| `teavel 모델` | 말을 알아듣는 언어 모델을 내려받습니다 (한 번만) |
| `teavel 설치` / `제거` | PowerShell 어디서나 실행되게 등록 / 해제 |

학교 전체를 다루는 것은 따로 있다 — 아래 [학교 M365 구성](#학교-m365-구성-관리자용).

| 명령 | 하는 일 |
|---|---|
| `teavel m365` | 학교 그룹·Teams 를 살펴보고 정리하고 만듭니다 |
| `teavel 명단 <파일>` | 명단 파일을 읽어 일곱 자리로 정리합니다 |
| `teavel 선생님 <이름>` | 선생님 계정을 이름으로 찾습니다 |

이 셋은 말로 해도 닿는다 — "반 팀 만들어줘" · "작년 팀 백업해줘" · "김하늘 선생님 계정 뭐야".

### 세팅 항목

| 단계 | 항목 |
|---|---|
| ① 이 컴퓨터와 계정 | 컴퓨터 이름 · **Windows 학교 계정 잇기** · OneDrive 로그인 · Office 로그인 · 아웃룩 메일 계정 |
| ② 자료 지키기 | 바탕 화면·문서·사진 백업 (알려진 폴더 이동) |
| ③ 프로그램 | Office · Teams · To Do · teaveloper 앱 |
| ④ 인쇄 | 기본 프린터 · 프린터 추가 (공유/IP) |

**학교 계정 잇기가 뿌리다.** Windows에 붙으면 아래 것들이 대부분 함께 풀린다.
그래서 점검 화면에서 이 항목이 걸리면 그 자리에 그렇게 적어 준다.

**컴퓨터 이름을 앞에 둔 이유**는 나중에 바꾸면 곤란해서다. 학교 계정을 잇거나
장치를 연결한 뒤에는 이름을 못 바꾼다 — Teavel 은 그때 거부하고 까닭을 알려 준다.
이름 규칙(15자 이하 · 한글 불가 · 영문·숫자·붙임표만)도 함께 짚어 준다.

### Home 이냐 Pro 냐 — 답이 달라진다

학교 계정을 넣는 방법은 **두 가지이고 결과가 다르다.** 여기서 선생님들이 갈린다.

| | ① 계정 추가 (등록) | ② 장치 연결 (Entra 조인) |
|---|---|---|
| Windows 로그인 | 지금 쓰던 그대로 | 학교 계정으로 바뀜 |
| 원드라이브·아웃룩·팀즈 | 이어짐 | 이어짐 |
| 학교가 이 PC를 관리 | 안 함 | **함** (원격 초기화 포함) |
| **Home 에서** | **된다** | **안 된다 — 메뉴 자체가 없다** |
| 알맞은 경우 | 개인 컴퓨터 | 학교에서 지급한 컴퓨터 |

Home은 ②가 **불가능하다.** 설정 화면 아래쪽의 "이 장치를 Microsoft Entra ID에 조인"
파란 글씨가 아예 나오지 않는다. 학교에서 "조직에 연결하세요"라고 안내받은 선생님이
그 메뉴를 찾다가 포기하는 지점이 정확히 여기다. Teavel은 그걸 **없는 게 정상이라고 알려 준다.**

Pro인데 개인 컴퓨터라면 ②를 **하면 안 된다.** 학교가 선생님 개인 PC에 정책을 걸 수 있게 된다.
그런데 설정 화면에서 ①과 ②는 같은 [연결] 단추 안에 나란히 있어서 헷갈리기 쉽다.

그래서 Teavel은 이 자리에서 **고쳐 주기보다 설명한다.**

```
> 학교 계정 어떻게 넣어요

  Windows Home 판
  지금 상태: 학교 계정이 연결돼 있지 않습니다.

  이 컴퓨터는 Home 판이라 ② 는 아예 불가능합니다. ① 로 하시면 됩니다.

    [설정] → [계정] → [회사 또는 학교 액세스] → [연결]
    → 학교 메일 주소 입력 → 비밀번호 입력 → 끝

  ※ 화면 아래에 "이 장치를 Microsoft Entra ID에 조인" 같은 파란 글씨가
     보이지 않는 것이 정상입니다. Home 에는 그 기능이 없습니다.
```

Pro라면 이 컴퓨터가 학교 것인지 개인 것인지 물어보고, 그에 맞는 쪽을 짚어 준다.

프린터는 말로도 시킬 수 있다 — "기본 프린터를 3층복도로 해줘", "교무실 프린터 연결해줘".
Windows가 *마지막에 쓴 프린터*를 기본으로 계속 바꾸는 설정도 함께 꺼 준다
(기본 프린터를 정해도 자꾸 바뀌는 원인이 이것이다).

처음이라면 **`teavel 점검`** 부터 하세요. OneDrive 로그인, 바탕 화면 백업,
Office 정품 인증처럼 안 돼 있으면 나머지가 불편해지는 것들을 짚어 줍니다.

## 학교 M365 구성 (관리자용)

학교의 M365 그룹·Teams를 정리하고 구성한다. 대상은 **학교의 M365 관리자** —
대개 전문가가 아니라 그 역할을 떠맡은 선생님이다. 일반 교사용 기능이 아니다.

```powershell
teavel m365
```

한 흐름으로 끝까지 간다. 관리자가 알아야 할 명령은 이것 하나다.

```
① 준비 확인    모듈이 갖춰졌는지 — 없으면 대신 설치한다
② 로그인       브라우저 창 안내
③ 재고         지금 있는 그룹·팀 · 사람 · 라이선스 없는 계정
③′ 이름 붙이기  성·이름이 나뉘어 있으면 붙이자고 권한다
④ 명단         파일을 받는다 — 학생 목록이자 학교 구조의 출처
⑤ 정리         이름 바꾸기 / 지우기 / 지난 학년도로 보관
⑥ 만들기       없는 반 팀 + 채널
⑦ 학생 넣기    반별로
⑧ 담임 선생님   반마다 소유자 지정
⑨ 마무리       활성화 · 표시 안내
```

**여러 번 돌려도 안전하다.** 이미 있는 것은 건드리지 않고, 학기 중 전학생이 한 명 오면
그 한 명만 넣는다.

### 학교 구조를 손으로 적게 하지 않는다

예전에는 `catalog/m365-tree.json` 에 "이 학교는 이런 모양이어야 한다" 를 적어야 했다.
그런데 **그 파일을 관리자가 고칠 리 없다** — 무엇을 적어야 하는지도 모르고,
적으라고 하는 순간 그 자리에서 막힌다.

그럴 필요가 없다. **명단에 이미 들어 있다.**

```
✓ 명단을 보니 이 학교는 이렇습니다 — 반 12개 — 1학년 4개 반 · 2학년 5개 반 · 3학년 3개 반
      1학년   1반(3명)  2반(3명)  3반(3명)  4반(3명)
      2학년   1반(3명)  2반(3명)  3반(3명)  4반(3명)  5반(3명)
      3학년   1반(3명)  2반(3명)  3반(3명)
  이 구조가 맞습니까? [Y/n]
```

명단이 없으면 선언 파일을 그대로 쓴다. 반 팀만 갈아 끼우고 교직원 그룹 같은 나머지는 둔다.

### 정리가 먼저다

학교엔 지난 몇 년치 그룹이 어질러져 있다. 새로 만들기 전에 그것부터 봐야 한다.

지우면 파일·대화가 함께 사라지므로 **지우기보다 먼저 두 가지 길을 준다** —
이름만 바꿔 살리기, 그리고 **지난 학년도로 보관**(이름 앞에 그 팀이 만들어진 연도를 붙이고
학생만 내보낸다. 팀·파일·대화는 그대로 남고 담당 선생님은 계속 볼 수 있다).

**선언에 있는 것은 정리 후보로 올리지 않는다.** 방금 만든 반 팀은 학생을 넣기 전이라
비어 있는데, 그것을 '쓰이지 않는 것 같다' 며 지우자고 하면 안 된다.

### 이름은 뼈대다

**학생 표시 이름은 `학번+이름`이어야 한다**(`10101김하늘`). 보기 좋으라는 것이 아니라
**교사와 학생을 가르는 근거**다. 선생님 계정은 이름만 있고 학생은 앞에 학번이 붙으므로,
이름으로 사람을 찾을 때 둘이 깔끔하게 갈린다. 이 규칙이 없으면 실제 운영에서 헷갈리고,
**학생을 팀 소유자로 넣으면 그 아이가 반 전체를 지울 수 있다.**

교육청 포털로 만든 교사 계정은 성과 이름이 **나뉘어** 들어가 화면에 `하늘 김` 처럼 뒤집혀 보인다.
김·이·박이 수십 명인 학교에서 이대로는 아무도 못 찾는다. 그래서 첫 과정에서 찾아내 붙이자고 권한다.

### 선생님은 명단이 필요 없다

교사 계정은 교육청에서 받아 이미 있다. **성함만 받아 찾는다** — 아이디는 몰라도
같이 근무하는 선생님 이름은 안다. 성만 넣어도 된다(`김`).

## 명단 읽기

```powershell
teavel 명단 <파일>
```

아무 표나 받아 **학년·반·번호·학번·이름·표시이름·ID** 일곱 자리에 꽂는다.

**양식을 정해 주지 않는다.** 학교마다 엑셀 모양이 다른데 "이 양식에 맞춰 오세요" 라고 하면
아무것도 모르는 관리자는 거기서 막힌다. 맞추는 쪽이 Teavel이다.

```
학년 ← 2번째 열 '학 년'          ('학 년' 은(는) 학년 입니다, 값도 맞습니다)
반   ← 3번째 열 '학급'           ('학급' 은(는) 반 입니다, 값도 맞습니다)
ID   ←?6번째 열 '사용자 ID(메일)'  ('사용자 ID(메일)' 안에 'id' 이(가) 있습니다)
쓰지 않은 열: 학년도, 담당교사
```

짐작한 것은 **반드시 보여 준다.** 조용히 틀리면 아이가 다른 반에 들어간다.
`?` 는 완전 일치가 아니라는 뜻이다.

| 걸리는 것 | 어떻게 |
|---|---|
| `학년도` 를 학년으로 읽음 | 점수 매기기 전에 잘라 낸다 |
| `일반계` 안의 `반` | 한 글자짜리는 부분 일치를 쓰지 않는다 |
| `학번` 과 `번호` | 한 열이 두 자리를 못 갖게 해 서로 밀어낸다 |
| 머리글이 첫 줄이 아님 | 줄마다 꽂아 보고 가장 많이 꽂히는 줄을 고른다 |
| 열 이름이 `열1` 뿐 | 값의 생김새로 본다(1~6이면 학년) |

### 없는 자리는 만들어 채운다

| 없을 때 | 무엇으로 |
|---|---|
| 학번 | 학년·반·번호를 이어 붙여 |
| 표시이름 | 학번+이름 |
| 학번·이름 | 표시이름을 갈라 (`30105강도윤`) |
| 학년·반·번호 | 학번을 갈라 |
| 학년·반 | 위쪽 제목줄에서 물려받아 (보고서 형식) |

**학번 규칙은 학교마다 다르다.** 1학년 3반 1번이 `10301` 인 학교도 있고 `1301` 인 학교도 있다.
한 학교에서 `1301`(1학년 3반 1번)과 `21005`(2학년 10반 5번)를 함께 본 적도 있다 —
반을 자리에 맞춰 채우지 않는 것이다. 그래서 **박아 두지 않고 자료에서 알아낸다.**
학번 열이 없어도 아이디(`s10203@…`)나 표시이름 안에 들어 있으면 거기서 찾아내
사람에게 아무것도 묻지 않는다.

### 데이터 형식과 보고서 형식을 가른다

**데이터 형식**은 줄마다 학년·반이 있다. **보고서 형식**은 `1학년 3반` 이 제목으로 한 번
나오고 그 아래에 번호·이름만 있다. 뒤엣것은 제목줄에서 학년·반을 읽어 다음 제목까지 물려준다.
한 파일에 여러 반이 이어 붙은 것도 이것으로 갈린다.

### Office 없이 읽는다

| | |
|---|---|
| `.csv` `.txt` `.tsv` | 직접. **CP949 를 자동으로 알아본다** |
| `.xlsx` `.xlsm` | 직접(zip+xml). 엑셀이 없어도 된다 |
| `.hwpx` | 직접(zip+xml). **한글이 없어도 된다** |
| `.xls` `.cell` `.hwp` | 못 읽음 — 어느 프로그램에서 무엇을 누를지 적어 준다 |

한셀만 깔린 PC 가 있어서 엑셀 COM 하나로는 안 된다. 한국 학교 csv 는 대개 CP949 라
UTF-8 로 읽으면 이름이 전부 깨진다.

### 계정을 한꺼번에 만들 것인가

학생 계정은 **학생이 스스로 만들거나, 관리자가 한꺼번에 만들거나** 둘 중 하나다.
이미 있는 계정을 쓰는 자리에서 또 만들면 같은 사람이 둘이 되고, 없는 계정에 배정하려 들면
한 줄도 못 넣는다. 그래서 반드시 사람이 정한다 — 다만 **"벌크로 만들까요" 라고 묻지 않는다.**

```
이 명단에 있는 학생들이 지금까지 학교 계정으로
Teams 나 아웃룩에 로그인해 본 적이 있습니까?
  [1] 아니요 — 계정이 아직 없습니다
  [2] 예 — 이미 쓰고 있습니다
  [3] 잘 모르겠습니다        ← 확인하는 방법을 알려 준다
```

한꺼번에 만들기를 고르면 **관리 센터에 올릴 csv** 를 만들어 준다. 계정 만들기는
Exchange·Teams 모듈로 안 되고 Graph 는 동의 화면을 부르는데, 이 길은 동의가 없고
학생 개인 정보가 우리 코드를 거쳐 밖으로 나가지 않는다.
열 이름은 짐작하지 않는다 — 관리자가 내려받은 견본을 받아 그 머리글을 그대로 쓴다.

설계 결정과 검증 상태는 [docs/m365.md](docs/m365.md) 에 있다.

## 설계

### 모델에게 코드를 짜게 하지 않는다

로컬 7B가 짠 PowerShell을 교사 PC에서 돌리면 학생 자료가 위험하고 품질도 들쭉날쭉하다.
그래서 **동작은 사람이 검증해 둔 PowerShell 함수**가 하고, 모델은 둘만 한다:

```
교사의 말
   ↓  ① 낱말로 먼저 본다 (0초, 대부분 여기서 끝난다)
   ↓  ② 애매하면 로컬 모델이 도구 하나를 고르고 인자를 뽑는다 (출력 ~60토큰)
{ "tool": "excel.merge_workbooks", "args": { "Folder": "...", "Sheet": 1 } }
   ↓  ③ 인자 검증 — 선언에 없는 이름·없는 경로는 여기서 걸린다
   ↓  ④ 검증된 PowerShell 함수 실행 (Office COM)
결과
```

모델은 **고를 뿐 실행하지 못한다**. 없는 도구 id를 말하면 버려지고, 지어낸 인자는 검증에서 걸린다.
모델이 아예 없어도 메뉴로 20가지를 전부 쓸 수 있다.

### 인자는 명령줄이 아니라 stdin JSON으로 넘긴다

모델이 채운 값이 명령줄에 문자열로 끼워지면 따옴표 하나에 명령이 갈라진다.
JSON + splatting으로 넘기면 값은 끝까지 값으로만 남는다 — 한글 경로·공백 폴더도 문제가 없다.

```
teavel.exe ──stdin JSON──> Invoke-TeavelTool.ps1 ──splat──> Merge-Workbook -Folder … -Sheet 1
```

### Windows 접점은 인터페이스 뒤에 둔다

`IRegistry`·`IProcessRunner`·`ISystemPaths`. 덕분에 리눅스에서도 로직을 빌드·검증할 수 있다
(`InMemoryRegistry`, `FakeProcessRunner`).

### 자동으로 못 하는 일은 그런 척하지 않는다

OneDrive·Office 로그인은 비밀번호가 필요해 대신 해 줄 수 없다.
창을 띄우고 **클릭 순서를 알려 준 뒤** `ManualStepStarted`로 정직하게 끝낸다.

## 개발

### 빌드

```bash
dotnet build Teavel.sln
dotnet run --project src/Teavel.Cli -- 목록
```

배포용 exe는 **teaveloper 포털에서 빌드**한다(앱 이름 통일성).
이 저장소는 소스만 제공하며 GitHub 릴리스로 exe를 배포하지 않는다.
포털이 읽는 빌드 선언은 뿌리의 `.teacherapp.yml` 이다.

```bash
./publish-win.sh            # 포털 파이프라인과 같은 것을 로컬에서
```

### exe 하나만 배포된다

포털 파이프라인은 `dotnet publish` 결과에서 **`.exe` 하나만** 집어 배포한다.
그 옆에 있던 `scripts\`·`catalog\` 는 그대로 버려진다 —
그대로 두면 교사가 받은 Teavel 은 PowerShell 모듈이 없어 아무것도 하지 못한다.

그래서 `Teavel.Core` 가 그 파일들을 `EmbeddedResource` 로 품고, 처음 쓸 때
`%LOCALAPPDATA%\Teaveloper\Teavel\runtime\` 으로 꺼내 놓는다
(`Platform/Payload.cs`). 꺼내는 이유는 PowerShell 이 **파일 경로로** 모듈을 불러오기
때문이다 — 메모리 안에서는 쓸 수 없다.

exe 옆에 진짜 `scripts\` 가 있으면 그쪽을 쓴다. 고쳐 가며 시험할 때 묻어 둔 것이
덮어써 버리면 곤란하다.

### 크기 — 144MB → 85MB

교사가 받아야 하는 양이라 그냥 둘 수 없었다. 재 보니 네이티브 93.7MB 중
win-x64 는 16.7MB 뿐이고 나머지 77MB 가 리눅스·macOS·ARM 용이었다
(LLamaSharp.Backend.Cpu 가 모든 플랫폼을 한꺼번에 담는다).

`Teavel.Cli.csproj` 의 `TeavelTrimForeignRuntimes` 가 걷어낸다.
**지울 것을 못 박아 둔다** — 처음에 "지금 RID 가 아닌 것을 다 지운다" 고 썼다가
win-x64 것까지 지웠는데 빌드는 멀쩡히 끝났다. 교사가 언어 모델을 쓸 때에야 터졌을 것이다.
어느 쪽으로 틀려도 안전한 쪽(조금 커질 뿐)으로 기울여 둔다.

AVX 갈래(avx·avx2·avx512·noavx)는 남긴다 — 어느 것을 쓸지는 그 PC 의 CPU 를 보고
실행 시점에 정해진다.

남은 85MB 중 68MB 는 .NET 런타임 자체다(자체 포함이라 교사 PC 에 런타임 설치가 필요 없다).

### 코드 서명 — exe만으로는 부족하다

**스크립트도 함께 서명해야 한다.** Teavel의 실제 동작은 `scripts/*.psm1`이 하는데,
이건 exe와 별개 파일이라 exe에 서명해도 서명되지 않은 채 남는다.

우리는 PowerShell을 `-ExecutionPolicy Bypass`로 부르지만 그건 **Process 범위**다.
실행 정책의 우선순위는 이렇다:

| 순위 | 범위 | |
|---|---|---|
| 1 | MachinePolicy | ← 그룹 정책 |
| 2 | UserPolicy | ← 그룹 정책 |
| 3 | Process | ← 우리 `Bypass`가 여기 |
| 4 | CurrentUser | |
| 5 | LocalMachine | |

학교가 관리하는 PC에서 `AllSigned`를 GPO로 걸어 두면 우리 `Bypass`는 무시되고
스크립트가 돌지 않는다. `RemoteSigned`도 안전하지 않다 — 압축을 받아서 푼 파일에는
'다른 컴퓨터에서 온 파일' 표시(MOTW)가 붙어 원격으로 취급되기 때문이다.

`publish-win.sh`는 `TEAVEL_SIGN_CMD` 가 설정돼 있으면 exe와 스크립트를 모두 서명한다.
**타임스탬프를 반드시 넣을 것** — 없으면 인증서 만료와 동시에 이미 배포된 판의 서명이 죽는다.

```bash
# Linux CI (jsign 은 PowerShell 스크립트 서명을 지원한다)
TEAVEL_SIGN_CMD='jsign --keystore … --alias … --tsaurl http://timestamp.digicert.com' ./publish-win.sh
```

서명은 **자가점검 다음**에 한다. 그 뒤로 스크립트를 한 글자라도 고치면 서명이 깨진다.
서명 블록은 파일 끝에 주석으로 붙을 뿐이라, 선생님이 열어서 읽을 수 있다는 성질은 그대로다.

교사 PC에서 이 문제에 걸렸는지는 `teavel 자가점검` 이 알려 준다.

### 도구 추가하기

두 곳을 짝으로 고친다.

1. `scripts/Teavel.Excel.psm1` 등에 함수를 하나 만든다.
   `New-TeavelResult -Message … -Details …` 를 돌려주고, 문제가 있으면 한국어로 `throw`.
2. `src/Teavel.Core/Tools/ToolCatalog.cs` 에 `ToolSpec` 을 하나 더한다.
   `ToolParam.Name` 은 PowerShell 매개변수 이름과 **정확히** 같아야 한다.

어긋나면 `teavel 자가점검` 이 잡는다 (빌드 스크립트가 이걸 실행하므로 어긋난 채로 배포되지 않는다).

```
✗ [excel.merge_workbooks] 'Merge-Workbook' 에 'Folder' 매개변수가 없습니다.
    (스크립트가 받는 것: Dir, HeaderRow, Output, Pattern, Sheet)
```

### 앱에 MCP를 붙일 때

Teavel이 MCP **호스트**다. teaveloper 앱이 MCP 서버가 되고 Teavel이 그 도구를 부른다.
앱에 MCP를 달았다면 `catalog/apps.json` 의 `mcp` 만 채우면 된다 — **Teavel 재빌드가 필요 없다.**

```json
{
  "id": "saenggibu-helper",
  "install": { "kind": "portal", "exe": "생기부도우미.exe", "installDir": "%LOCALAPPDATA%\\Teaveloper\\saenggibu" },
  "mcp": { "args": ["--mcp"], "minVersion": "1.2.0" }
}
```

`command` 를 비우면 앱 실행 파일 자신을 서버로 띄운다. `minVersion` 은 MCP를 갓 붙이기 시작했을 때
옛 버전이 깔린 PC에 엉뚱하게 연결되는 것을 막는다.

### 언어 모델

생기부 도우미(LLLM)와 같은 방식 — 앱이 최초 실행 시 내려받는다(이어받기·GGUF 검증).
주소는 `TeavelModelConfig.ModelUrl` 에 **리터럴로 박혀 있다**(우리 Azure Blob, 읽기전용
SAS). 환경변수 `TEAVEL_GGUF_URL` 은 갈아끼우기용이지 배포 수단이 아니다 — 그 값은 교사
PC 에서 실행 시점에 읽히므로 빌드 때 켜 두면 아무 일도 일어나지 않는다.

찾는 순서: `TEAVEL_MODEL` → exe 옆 `models/` → Teavel 데이터 폴더 → **생기부 도우미의 `models/`**.

| | Teavel | 생기부 도우미 (공유 대상) |
|---|---|---|
| Windows | `%LOCALAPPDATA%\Teaveloper\Teavel\models` | `%LOCALAPPDATA%\SaenggibuHelper\models` |
| Linux | `~/.local/share/Teaveloper/Teavel/models` | `~/.local/share/saenggibu-helper/models` |

생기부 도우미 경로는 그쪽 `MainWindow.DataDir()` 규칙과 같아야 한다. 어긋나면 공유가
조용히 안 될 뿐이라 눈치채기 어렵다.

여러 개가 잡히면 **Teavel 전용 → 범용 instruct → 그 외** 순으로 고르고, 같은 등급이면 작은 것을 쓴다.
생기부 도우미의 모델은 생기부 문장 쓰기에 맞춰 따로 학습된 것이라 지시 따르기에는 불리하다 —
그것을 빌려 쓰는 중이면 `teavel 자가점검` 이 알려 준다.

기본값은 **1.5B급**이다. 도구 중 하나를 고르는 일에 7B는 필요 없고,
RAM 8GB에서 생기부 도우미(4.7GB)와 부딪히지 않아야 한다.

### RAM — 어디서 얼마나 쓰나

7B 모델로 실측한 값이다(RssAnon = 실제로 점유한 물리 메모리).

| | 익명 메모리 |
|---|---|
| 모델 가중치 (파일 4,466MB) | **3,029MB** |
| 도구 고르기 문맥 (1024) | +245MB |
| 인자 뽑기 문맥 (768) | +96MB |

**모델 가중치가 거의 전부다.** 문맥을 아무리 조여도 5% 안쪽이다.
그러니 RAM 을 아끼는 유일한 진짜 방법은 **작은 모델을 쓰는 것**이다 — 1.5B면 여기가 1/4로 준다.

mmap 은 이미 켜져 있다(`UseMemorymap = true`, 기본값이지만 명시해 두었다).
그런데 파일 4,466MB 중 3,029MB가 익명으로 올라온다 — llama.cpp 가 CPU(AVX2)용으로
가중치를 재배치(repack)하면서 파일 매핑이 아니라 실제 RAM 으로 복사하기 때문이다.
속도를 위한 것이라 끄지 않는다. **mmap 이 켜져 있다고 해서 모델이 RAM 을 안 먹는 것은 아니다.**

그래서 한 가지를 바로잡아 둔다 — **생기부 도우미와 모델 파일을 공유해도 RAM 은 거의 안 아낀다.**
공유의 이득은 *다시 내려받지 않는 것* 이지 메모리가 아니다. repack 된 부분은 앱마다 따로 든다.
두 앱을 동시에 띄우면 8GB 에서는 빠듯하니, Teavel 은 작은 모델을 따로 쓰는 편이 낫다.

두 가지는 구조로 아꼈다.

- **문맥 크기를 용도별로** — 도구 고르기 1024(프리픽스 730), 인자 뽑기 768. 예전엔 둘 다 2048.
- **인자 뽑기 문맥은 필요할 때만 만든다** — 인자가 전부 경로인 도구(프린터 목록, 파일 살펴보기)는
  그 단계를 건너뛰므로, 미리 만들면 쓰지도 않을 KV 캐시를 물고 있게 된다.

도구를 늘려 지시문이 문맥의 3/4을 넘으면 `LlmSession` 이 만들어질 때 바로 실패한다.
조용히 이상해지는 것보다 낫다.

### 자가점검이 잡는 것

`teavel 자가점검` — 빌드 스크립트가 이걸 실행하므로 어긋난 채로 배포되지 않는다.

- 도구 선언 ↔ PowerShell 함수·매개변수 대조
- `Export-ModuleMember` 누락 (정의는 됐는데 밖에서 못 부르는 것)
- **UTF-8 BOM 없는 스크립트** (한국어 Windows 에서 안내문이 깨진다)
- **`param()` 이 있는 함수 안의 `@args`** (인자 없이 조용히 성공한다)
- **`List[object]` 를 `@()` 로 감싸는 것** (인수 형식이 일치하지 않습니다)
- **테넌트를 바꾸는 명령을 확인 창 대비 없이 부르는 것**

마지막 넷은 전부 실기에서 한 번씩 당한 뒤에 넣은 것이다.

### 재보는 법

```bash
dotnet run --project tools/Teavel.Eval -- keyword          # 낱말 라우터만
dotnet run --project tools/Teavel.Eval -- model <모델.gguf> # 로컬 언어 모델
dotnet run --project tools/Teavel.Eval -- morph            # 형태소가 어떻게 쪼개지는지
```

형태소 분석기를 **뺀 채로 재려면 폴더를 잠시 치워야 한다.** `TEAVEL_KIWI_MODEL` 을 없는
곳으로 줘도 뒤의 후보 경로(생기부 도우미 것 포함)에서 찾아내기 때문이다 — 그것도 모르고
"차이가 없다" 고 적을 뻔했다.

문장 세트는 `tools/Teavel.Eval/Program.cs` 에 박아 두었다(24문장). 도구 id 가 바뀌면
실행 즉시 걸러 준다 — 안 그러면 '영원히 틀리는 문장' 이 생기고 모델 탓으로 오해된다.

> **아래 두 표의 수치는 이 도구가 생기기 전에 잰 것이라 재현할 수 없다.** 그때 쓴
> 문장이 저장소에 남아 있지 않다. 지금 세트로 새로 재면 값이 다르게 나오는 것이
> 정상이며(난이도가 다르다), 비교는 **같은 세트를 여러 라우터에 돌려** 해야 한다.
**실측(2026-08-15, Windows, 24문장, Qwen2.5-1.5B-Instruct Q4_K_M):**

| | 모델 없음 | 모델(가드 없음) | **모델 + 가드** |
|---|---|---|---|
| 바로 실행 · 맞음 | 4 | 17 | **14** |
| 바로 실행 · 틀림 | **0** | 4 | **0** |
| 골라야 함 (정답이 목록에 있음) | 19 | 3 | 10 |
| 못 알아들음 | 1 | 0 | **0** |
| 명령당 시간 | 0초 | ~7.5초 | ~7초 |

**가드가 없으면 모델은 명백한 개선이 아니다.** 틀린 4건은 전부 *모델이 없었으면 목록이
떠서 교사가 맞게 골랐을* 문장이었다 — 모델이 문제를 푼 게 아니라 안전한 선택지를 없앤
셈이다. 10초를 기다리게 하면서 5번에 1번 엉뚱한 화면을 띄우는 것은 설득이 안 된다.

가드(모델과 낱말의 1순위가 갈리면 고르게 함)를 넣으면 **모델 없는 경우를 모든 축에서
이긴다** — 즉시 정답 4→14, 목록 고르기 19→10, 못 알아들음 1→0, 틀린 실행은 0 유지.
즉시 정답 3건을 내주고 위험한 4건을 없애는 교환이다.

**측정은 부품이 아니라 교사가 겪는 것을 센다.** 낱말 라우터의 '1순위 정답률' 은 교사
경험이 아니다 — 점수가 확신 문턱(0.55) 아래면 어차피 교사에게 고르게 하기 때문이다.
그리고 언어 모델은 자기 답에 늘 0.8 을 매기므로, **모델이 답하면 교사는 고를 기회 없이
그 도구를 만난다.** 그래서 모델에게 물어야 할 것은 정확도가 아니라 이것이다:

> 고르는 수고를 몇 번이나 없애 주고, 그 대가로 몇 번이나 **틀린 도구를 조용히 실행**하는가.

이득과 손해가 같은 메커니즘(문턱을 넘는 0.8)에서 나오므로 함께 봐야 한다.
지금 낱말 라우터만 쓸 때 '틀린 실행' 은 0 이다 — 모델은 이 값을 지키면서 '바로 실행·맞음'
을 올려야 값을 한다.

### 낱말 라우터는 어디까지 되는가

측정해 본 결과다. 문장은 모두 직접 지었으므로 참고치이지 엄밀한 평가가 아니다.

| 문장 | 1순위 정확 | 3순위 안 | 즉시확정 |
|---|---|---|---|
| 카탈로그 예시와 비슷한 표현 | 16/16 | — | 16/16 |
| 예시와 다른 표현 (세트 A) | 6/13 | 11/13 | 1/13 |
| 예시와 다른 표현 (세트 B) | 6/13 | 10/13 | 0/13 |

**유의어(`ToolSpec.Aliases`)를 붙여도 달라지지 않았다.** 붙이기 전 5~6/13, 붙인 뒤 6/13 —
표본 13개에서는 노이즈다. 실패를 뜯어보니 조사·어미 문제가 아니라 유의어와 상식 문제였고,
유의어 목록으로 메울 수 있는 건 그중 일부뿐이었다.

형태소 분석기도 마찬가지다. **붙여서 재 봤고, 정답률은 오르지 않았다** — 아래 표에 있다.

그래서 **로컬 모델은 선택이 아니라 필수다.** 낱말 라우터의 역할은 두 가지로 좁혀 둔다:

- 예시에 가까운 흔한 말을 **0초에 처리**하는 빠른 길 (모델을 부르지 않아도 된다)
- 모델이 없을 때 **후보 목록**을 내주는 바닥 (정답이 3순위 안에 들 확률이 높다)

확신 문턱(0.55) 아래면 넘겨짚지 않는다. 모델이 있으면 넘기고, 없으면 교사에게 고르게 한다.
위 표에서 '즉시확정'이 사실상 0인 것은 라우터가 **모르는 것을 안다**는 뜻이라 바람직하다.

유의어는 그래도 남겨 두었다 — 낱말 라우터보다 **언어 모델 프롬프트에서 값을 한다**
(도구 목록에 "비슷한 말"로 함께 실린다).

### 형태소 분석기는 무엇을 고쳤나

낱말 라우터의 어간 처리는 **끝 한 글자를 떼는 것**이 전부였다. 그래서 이게 샜다.

```
  교사: "엑셀 좀 합쳐줘"   →  합쳐줘 · 합쳐
  우리: "합치기"           →  합치기 · 합치
                              ↑ 둘이 안 맞는다
```

Kiwi(0.23.2)를 붙이면 둘 다 `합치` 가 된다. **생기부 도우미가 쓰던 것을 그대로 가져왔다** —
우리가 손볼 것이 없는 부품이라 두 벌 만들 까닭이 없고, 그쪽이 이미 받아 두었으면 빌려 쓴다.

같은 24문장을 세 가지로 돌린 실측이다(모델 없이, 낱말 라우터만).

| 교사가 보는 것 | 형태소 없음 | 형태소만 | **둘 다 (지금)** |
|---|---|---|---|
| 바로 실행 · 맞음 | 4 | 4 | 3 |
| 바로 실행 · **틀림** | 0 | 0 | **0** |
| 골라야 함 (정답이 목록에 있음) | 19 | 19 | **21** |
| 골라야 함 (정답이 **없음**) | 0 | **1** | **0** |
| 못 알아들음 | **1** | 0 | **0** |

**정답률은 오히려 1건 내려갔다.** 그런데도 붙인 이유는 오른쪽 두 줄에 있다 —
**막다른 길이 둘 다 0 이 되는 유일한 구성**이다. 24문장 전부가 '바로 맞거나, 정답이 든
목록을 보거나' 로 끝난다.

내려간 까닭은 구조적이다. 겹침 점수를 **교사가 말한 낱말 수로 나누기** 때문에, 형태소를
더하면 분모가 커져 점수가 확신 문턱(0.55) 아래로 내려간다. 즉 **즉시 정답 1건을 내주고
막다른 길 1건을 없애는 교환**이고, 넘겨짚지 않되 정답은 반드시 목록에 있어야 한다는
설계에는 이쪽이 맞다.

형태소만 쓰면 분모 문제는 없지만 붙여 쓴 말('압축파일')을 놓쳐 **정답이 목록에서 빠지는**
경우가 생긴다. 그게 표의 가운데 칸이다.

> **모델과 네이티브의 판이 반드시 같아야 한다.** 다른 판을 섞으면
> `Cannot open morphology file 'sj.morph'` 로 끝난다 — 실제로 0.23.0 모델에 0.23.2
> 네이티브를 물려 당했다. 그래서 둘 다 같은 GitHub 릴리스에서 받는다.

없어도 Teavel 은 그대로 돈다. 학교 인터넷이 느려 안 받은 분도 있을 것이고,
그때 아무것도 못 하게 되면 안 된다.

**바로 되는 비율이 3배가 되고, 엉뚱한 것을 실행한 경우가 0건이다.**
못 알아듣는 문장도 사라진다. 로컬 모델이 선택이 아니라는 근거가 이것이다.

'골라야 함' 이 나쁜 것만은 아니다 — 확신이 서지 않을 때 넘겨짚는 대신 교사에게 묻는
설계의 결과이고, 그 11건 모두 정답이 목록 안에 있었다.

**7B 를 기본값으로 쓰지 않는 이유**도 이 표에 있다. 5건을 더 맞히지만 명령당 29초다.
"엑셀 합쳐줘" 하고 30초를 기다리는 도구는 안 쓰게 된다. RAM 도 4배 든다(3.0GB vs 0.7GB).

그리고 이 표가 **파인튜닝이 값어치 있는 자리**를 정확히 짚어 준다. 13 → 18 의 간격은
구조의 한계가 아니라 작은 모델의 판단력 문제다. 다만 학습 목표는 "이 도구 목록을 외우기"
가 아니라 **"프롬프트에 실린 목록에서 고르는 능력"** 이어야 한다 — 앱에 MCP 를 붙이면
도구가 늘어나는데, 목록을 외우게 하면 그때마다 재학습해야 해서 카탈로그 기반 확장성이 무너진다.

속도를 5.5배 줄인 세 가지는 전부 처음 구현의 잘못이었다:

1. **채팅 템플릿을 안 썼다.** instruct 모델은 자기 형식(`<|im_start|>…`)으로 학습됐는데
   평문으로 밀어 넣고 있었다. `LLamaTemplate` 으로 모델 자신의 템플릿을 쓴다.
2. **안 변하는 앞부분을 매번 다시 읽었다.** `StatelessExecutor` 는 호출마다 도구 목록 전체를
   재처리한다. 그 목록은 항상 똑같다 — 한 번만 처리하고 KV 상태를 저장해 두었다가
   매 요청은 거기서 이어 간다(`LlmSession`). 이게 가장 큰 몫이었다.
3. **프롬프트가 길었다.** 도구마다 제목·예시·유의어를 다 실었다. `id = 제목 (유의어 6개)` 로 줄였다.

여기에 **7B → 1.5B** 로 내리면 2~3초대가 된다(기본값이 1.5B인 이유).
게다가 흔한 말은 낱말 라우터가 0초에 처리하므로 모델을 부르는 일 자체가 드물다.
